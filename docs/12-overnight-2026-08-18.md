## What actually produced the matches

Ranked by how much they were worth, which is not the same as how clever they
were.

1. **Fixing the merge tool.** `scripts/merge_matches.py` was injecting its own
   block-scope externs into candidates that already declared their own, and
   always as `char`. Both bugs rejected functions that had genuinely matched.
   Fixing them recovered 135 functions in `rel_duel_eng` in a single run, before
   any new decompilation happened at all.
2. **Recognising families rather than functions.** A module's unmatched
   functions are not N independent puzzles. `rel_duel_eng` turned out to be full
   of leaf "trampolines" around three heavily-reused dispatchers; `rel_story`
   had 41 accessors on one shared object; `rel_deck`, `rel_deckswap` and
   `rel_decktutorial` are built from shared source. Identifying a family once
   paid out dozens of times. The catalogue is in
   `docs/11-reproducing-the-pipeline.md`.
3. **Correcting wrong assumptions.** Four times, a group of functions had been
   written off wholesale for a shared symptom, and re-diagnosing them
   individually found the group was wrong: the "commutative addu" family was far
   narrower than reported, the "beyond the register model" functions simply had
   nine or more arguments, and the `mult`/`mflo` bucket yielded once looked at
   one at a time. **Grouping by symptom and then reasoning about the group is
   how reachable work gets lost.**

## New tooling

| script | what it does |
|---|---|
| `scripts/find_twins.py` | groups duplicate functions within and across modules; `--apply` copies a matched body onto its exact duplicates and verifies. Konami shipped the same function at many addresses |
| `scripts/leaf_trampolines.py` | drafts C for single-call leaf functions by symbolically evaluating each outgoing argument register back to a struct field, parameter, immediate or symbol address |
| `scripts/permute.py` | scaffolds decomp-permuter for any function |
| `scripts/infer_arity.py` | extended to infer arity for each module's own internal functions, not just engine imports — 6,330 covered |

`scripts/leaf_trampolines.py` is narrower than hoped: it finds 0-2 candidates
per module outside `rel_duel_eng`, where it found 95. The dispatcher-with-many-
thin-wrappers architecture is specific to the duel engine.

`scripts/permute.py` produced nothing. 777,000 iterations against
`rel_html_view`'s last unmatched function never improved on the base score.

## Things that went wrong

Recorded because they cost real work and will recur.

- **`git add -A src/` is dangerous here.** It swept an agent's mid-edit file
  into an unrelated commit, and separately committed a truncated
  `src/rel_html_view.c` that dropped the module from 15 matched functions to 0.
  The full-project sweep caught it; a running total would not have. Commit only
  the specific files a piece of work owns.
- **`scripts/prune_module.py` emptied a source file** holding 22 verified
  functions. Its comment-removal loop popped lines until one began with `/*`,
  and popped the whole file when none did. Now bounded, with a regression test.
- **Agents that background their work lose all of it.** Five did. Every agent
  prompt now forbids `&`, `nohup` and monitor-and-wait patterns outright.
- **`grep MATCH` also matches `SIZE MISMATCH`.** It burned three agents
  independently. Use `\bMATCH\b`.
- **A function that matches alone can still fail in the file.** Per-function
  trials are candidates, not results; only a whole-file rebuild counts.

  either the original source or a systematic search, and recognising them early
  saves hours.
