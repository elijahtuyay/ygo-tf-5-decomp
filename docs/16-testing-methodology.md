# Testing methodology: keeping matched modules matched

The verification tools were always strict; what kept failing was the
*methodology around them* — matched work regressed after the fact and nothing
noticed. This doc defines the test cadence, the regression gate, and the rules
that make a regression impossible to commit silently. The standard everywhere
is the decomp.me equivalent: `MATCH` from `scripts/mwcc_diff.py` is score 0,
and 100% is the only acceptable result.

## 1. The incidents this design answers

Every mechanism below exists because of a specific, real failure:

| incident | root cause | answered by |
|---|---|---|
| `rel_html_view` dropped 15 → 0 matched, committed, unnoticed for hours | a truncated file swept in by `git add -A src/`; only running totals were tracked | the baseline gate (§3) + named-file `git add` |
| running total ~200 functions higher than reality | counts accumulated instead of measured | lists-not-counts baseline; `progress.py` as sole counter |
| `rel_movie_viewer`/`rel_html_view` "failed" relink; stale passes equally possible | SRC and non-SRC builds shared `build/<m>.elf`/`.prx` | split outputs: `build/<m>.src.elf`/`.src.prx` (Makefile, fixed 2026-08-18) |
| 171 functions recorded matched that were not | differ compared reloc symbol+kind only, not the instruction | full-instruction masked compare; the "only tighten" rule |
| functions matched alone, broke the file | file-scope extern flavours coupling functions | `merge_matches.py` whole-file verify + rollback; bisection procedure (docs/14 §4) |
| 3 agents misread `SIZE MISMATCH` as `MATCH` | substring grep | `grep '\bMATCH\b'` everywhere |
| `prune_module.py` emptied a 22-function file | unbounded comment scan | bounded scan + no-op regression test on 3 modules |

## 2. The verification pyramid — what runs when

| level | command | cadence |
|---|---|---|
| 1. function | `mwcc_build.sh` + `mwcc_diff.py … func_X` | every draft iteration |
| 2. whole file | `mwcc_build.sh` + `mwcc_diff.py` (no func arg) | every insertion/edit of `src/<m>.c` — a per-function pass is only a candidate |
| 3. regression gate | `scripts/check_regressions.py` | **before every commit that touches `src/`** |
| 4. module layout | `make MODULE=<m>` (from clean) | after any change to `config/`, `asm/`-generation, `asm_prepare.py`, or the Makefile |
| 5. module from source | `make MODULE=<m> SRC=1` | definition of done for a module; run when a module claims completion |
| 6. full sweep | `check_regressions.py --all` + relink sweep of all 28 from clean | end of every working session; before any push that aggregates multiple agents' work |

## 3. The regression gate

`scripts/check_regressions.py` + `config/progress-baseline.json`.

The baseline is the committed list of matched function **names** per module
(`{"generated": "YYYY-MM-DD", "modules": {"rel_gallery": ["func_00000138", …]}}`)
— names, not counts, so a failure names exactly what was lost. It was
generated by a full measured sweep (3,348 functions, 2026-08-18) and is
updated only by the script, never by hand.

Rules:

- **Default run** checks every module with uncommitted `src/` changes:
  recompiles with the real mwccpsp, re-diffs, and exits 1 naming any
  previously-matched function that no longer matches. Run it before every
  commit; a `REGRESSION` line means fix or revert — never commit through it.
- **`--update`** records new gains. Refresh the baseline **in the same commit
  as the matches it reflects**, so baseline and source never drift.
- **The baseline may only grow.** `--update` refuses to shrink it without
  `--force`; shrinking is a deliberate, explained act (e.g. a differ
  tightening invalidating old matches), never a routine one.
- If the baseline disagrees with a fresh measure and you did not just match
  something, **the code regressed, not the baseline**.

## 4. Build-state hygiene

- SRC and non-SRC builds write different artifacts; a mode switch can no
  longer contaminate verification. If any verify result surprises you,
  `make MODULE=<m> clean` and re-run before drawing conclusions — a
  conclusion drawn from a dirty build directory is void.
- Level-4/6 relink sweeps run **from clean**, always. The stale-output bug
  was found because a sweep skipped this; it stays policy so the next such
  bug is found the same way.
- `asm/` and `build/` are generated and gitignored. Nothing under them is
  ever evidence by itself; evidence is a gate command's output.

## 5. Reporting discipline

- The only citable numbers are `scripts/progress.py` output (and the baseline
  it agrees with), stamped with the date measured. Anything else is an
  estimate and must be labelled as one.
- A module's status is its highest *passing* gate, nothing more:
  "level 2 verified" ≠ "matching", "matched alone" ≠ "matched".
- Report failures verbatim (the gate's own output), including the ones you
  caused; a skipped gate is reported as skipped. The truncation incident
  stayed invisible precisely because reporting was optimistic.

## 6. Known holes, kept visible

- `src/rel_html_view.c` carries the one deliberately NONMATCHING function
  (`func_00000470`); the baseline lists only the 15 matched, so it cannot
  mask a real regression, but whole-file diffs of that module always show one
  mismatch. Do not "fix" this by loosening anything; it closes when the
  function matches or moves behind a `NONMATCHING` guard (docs/13 item 0.6).
- `rel_cutin_viewer` and `rel_duel_draw` fail level 4 (dangling `.L` labels
  from `asm_prepare.py` rewrites — docs/13 item 0.1). Until fixed, their
  matches rest on levels 1–3 only; treat their totals accordingly.
- The differ's addend blind spot (docs/14 §5) undercounts. That is the
  correct direction of error and stays until fixed properly (docs/13
  item 0.3).
