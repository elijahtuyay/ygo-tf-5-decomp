## 1. The size cliff is a chain of gates, and we were fixing the wrong one

Match rate collapses with function size (11% at 80 instructions, 0.08% at 160,
0% beyond). The obvious explanation is type guessing, and the arithmetic fits
perfectly: the median number of independent type decisions is 3 at <=20
instructions and 22 above 160, and 11% success at 6 decisions implies p~0.69,
which predicts 0.9% at 12 and 0.02% at 22 — exactly what we see.

So `scripts/gen_types.py` was written to remove the guessing: it reads every
access to every global across a whole module and emits the one type the binary
proves. 3,460 of 3,526 globals have a decidable type.

**Then an A/B test showed it changed nothing**, because on a sample of 31
unmatched medium functions **29 never compiled at all**. Types were the third
gate; we were failing the first. The lesson is now in docs/11: measure which
gate is failing before optimising anything.

## 2. Gate 1: m2c artifacts, four classes fixed

| artifact | count | fix |
|---|---:|---|
| `GLOBAL.unkNN` dot form on a scalar | 12 | rewrite to `*(T *)((char *)&GLOBAL + 0xNN)` |
| `void *` / `T *` temps assigned ints | 9 | declare those locals `int`; both are 32 bits in the same register and later uses are explicit casts |
| `*(void **)ADDR` loads | 3 | rewrite to `*(int *)` to match |
| `(*(int *)0xADDR)->unkNN` | 2 | bounded rewrite (the left side is exactly a dereferenced constant) |

Compile failures on that sample went **29 -> 18**, and functions reaching the
structural check went **2 -> 13**.

**Not attempted, deliberately:** casting `(*(int *)(...))(args)` to a function
pointer. The inner expression is parenthesised and a regex cannot find its end —
a non-greedy match runs past the closing paren to a later `))(` and emits
unbalanced output. docs/11 already recorded that trap for the arrow form; I hit
it again and reverted. Worth ~3 functions, needs a real parser.

## 3. A bug in my own type inference

`gen_types` marked 182 globals ambiguous. Most were not: **a store does not
carry signedness.** `sb` is what MWCC emits for both `char` and `unsigned char`;
only a load distinguishes them. Letting stores vote marked every global stored
with `sh` and loaded with `lh` as "seen as s16, u16". Separating width from
signedness took ambiguous from **182 to 66** and immediately closed a
28-instruction function whose only remaining diffs were `sh` rendered as `sb`.

## 4. Declare externs at BLOCK scope, always

A generated function that declares globals at file scope breaks the whole
translation unit, because `src/<module>.c` already carries block-scope externs
from earlier merges that disagree with it — `extern int D_003268E8;` as a scalar
where the new function needs an array. Two block-scope declarations in different
functions never conflict; a file-scope one conflicts with all of them.

The symptom is badly misleading: the function matches perfectly on its own and
then silently contributes nothing, because the whole-file verify fails to
compile and rolls it back. Moving the declarations inside the body took a
cluster from 0 added to 6.

## 5. New tooling

- **`scripts/near_misses.py`** — the work queue sotn-decomp has and we lacked:
  every unmatched function ranked by how close the automated pass got. It found
  a cluster of sibling functions all one instruction from matching, which is how
  the state-init family got solved.
  *It also taught a lesson:* the first version read stale sharded caches and
  reported 522 functions at one diff, most of which were already matched. It now
  filters against the verified baseline.
- **`scripts/gen_types.py`** — module-wide global types (3,460 determined).
- **`scripts/const_trampolines.py`** — two-instruction tail calls passing one
  constant argument. Only 1 candidate remains project-wide; the shape was
  already fully harvested.
