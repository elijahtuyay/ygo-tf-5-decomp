## Results

| | before | after |
|---|---:|---:|
| functions matched | 3,510 | **3,517** |
| bytes of `.text` | 138,568 | **139,348** (2.67%) |

The headline number is small. What changed is the diagnosis, and three tools
that make the remaining work visible and mechanical.

## 1. The size cliff is a chain of gates, and we were fixing the wrong one

Match rate collapses with function size (11% at 80 instructions, 0.08% at 160,
0% beyond). The obvious explanation is type guessing, and the arithmetic fits
perfectly: the median number of independent type decisions is 3 at <=20
instructions and 22 above 160, and 11% success at 6 decisions implies p~0.69,
which predicts 0.9% at 12 and 0.02% at 22 — exactly what we see.

So `scripts/gen_types.py` was written to remove the guessing: it reads every
access to every global across a whole module and emits the one type the binary
proves. 3,460 of 3,526 globals have a decidable type.

**Then an A/B test showed it changed nothing**, because on a sample of 31
unmatched medium functions **29 never compiled at all**. Types were the third
gate; we were failing the first. The lesson is now in docs/11: measure which
gate is failing before optimising anything.

## 2. Gate 1: m2c artifacts, four classes fixed

| artifact | count | fix |
|---|---:|---|
| `GLOBAL.unkNN` dot form on a scalar | 12 | rewrite to `*(T *)((char *)&GLOBAL + 0xNN)` |
| `void *` / `T *` temps assigned ints | 9 | declare those locals `int`; both are 32 bits in the same register and later uses are explicit casts |
| `*(void **)ADDR` loads | 3 | rewrite to `*(int *)` to match |
| `(*(int *)0xADDR)->unkNN` | 2 | bounded rewrite (the left side is exactly a dereferenced constant) |

Compile failures on that sample went **29 -> 18**, and functions reaching the
structural check went **2 -> 13**.

**Not attempted, deliberately:** casting `(*(int *)(...))(args)` to a function
pointer. The inner expression is parenthesised and a regex cannot find its end —
a non-greedy match runs past the closing paren to a later `))(` and emits
unbalanced output. docs/11 already recorded that trap for the arrow form; I hit
it again and reverted. Worth ~3 functions, needs a real parser.

## 3. A bug in my own type inference

`gen_types` marked 182 globals ambiguous. Most were not: **a store does not
carry signedness.** `sb` is what MWCC emits for both `char` and `unsigned char`;
only a load distinguishes them. Letting stores vote marked every global stored
with `sh` and loaded with `lh` as "seen as s16, u16". Separating width from
signedness took ambiguous from **182 to 66** and immediately closed a
28-instruction function whose only remaining diffs were `sh` rendered as `sb`.

## 4. Declare externs at BLOCK scope, always

A generated function that declares globals at file scope breaks the whole
translation unit, because `src/<module>.c` already carries block-scope externs
from earlier merges that disagree with it — `extern int D_003268E8;` as a scalar
where the new function needs an array. Two block-scope declarations in different
functions never conflict; a file-scope one conflicts with all of them.

The symptom is badly misleading: the function matches perfectly on its own and
then silently contributes nothing, because the whole-file verify fails to
compile and rolls it back. Moving the declarations inside the body took a
cluster from 0 added to 6.

## 5. New tooling

- **`scripts/near_misses.py`** — the work queue sotn-decomp has and we lacked:
  every unmatched function ranked by how close the automated pass got. It found
  a cluster of sibling functions all one instruction from matching, which is how
  the state-init family got solved.
  *It also taught a lesson:* the first version read stale sharded caches and
  reported 522 functions at one diff, most of which were already matched. It now
  filters against the verified baseline.
- **`scripts/gen_types.py`** — module-wide global types (3,460 determined).
- **`scripts/const_trampolines.py`** — two-instruction tail calls passing one
  constant argument. Only 1 candidate remains project-wide; the shape was
  already fully harvested.

## Follow-through: gate 1 fixed at scale (+33 functions)

The census above was run on 31 functions, which was too small to say which
artifacts dominate. Re-run on **300** compile-failing functions, the ranking was
different and pointed at one thing the earlier sample barely showed:

| artifact | share of 300 |
|---|---:|
| field access on a PARENTHESISED expression, `(base + i*0x14)->unk34` | 28 + much of 52 "pointer/array required" |
| `&GLOBAL + expr` byte arithmetic scaled by the global's type | 28 + 22 |
| miscellaneous m2c give-ups (`bitwise`, `saved_reg_s0`, `sp`) | ~10 |

**Two fixes, both of which the previous session had explicitly avoided:**

1. **A paren-aware arrow rewriter.** docs/11 recorded that a regex cannot find
   where a parenthesised left-hand side begins, and an earlier attempt emitted
   unbalanced output. True — so this scans backwards with a paren counter
   instead, which can. That is not a cleverer regex, it is the right tool.
2. **Byte-accurate global arithmetic.** m2c writes `&D_0034E660 + (i * 0xB3C)`
   where the offset is in BYTES, but `&D_x` now carries the measured type, so C
   scaled it by the element size and the address came out wrong. Casting the
   base to `int` restores byte arithmetic and makes the result assignable.
   Ironically this bug was *introduced* by the type work — a good example of why
   each change needs re-measuring rather than assuming.

**Measured on 60 functions that previously all failed to compile:** 37 now
compile and 3 match outright.

Applied across 21 modules: **+33 functions**, spread over ten of them —
rel_field +6, rel_duel_mgr +7, rel_story +4, rel_deckswap +4, rel_decktutorial
+4, and singles elsewhere. Total now **3,550 / 14,083 (2.73% of bytes)**.

## The m2c give-ups turned out to be a small class — and a lesson in self-inflicted errors

Chasing "m2c gave up" artifacts (`bitwise`, `saved_reg_s0`, bare `sp`) was the
stated next step. Measuring first showed it was the wrong target: in 250 drafts
`bitwise` appeared **once**, `saved_reg` **never**, and most `spNN` hits were
just m2c declaring ordinary stack locals, not failures. The whole class is
roughly 3% of compile failures. It is not worth tooling.

Re-censusing to find what actually dominated produced an uncomfortable answer:
**34% of remaining compile failures were caused by my own previous fix.**
Casting `&D_x` to int made byte offsets scale correctly but broke every
`*(base + off)` dereference, because an int cannot be dereferenced. Two repairs
followed, both measured on a fixed 60-function sample:

| change | compile failures / 60 |
|---|---:|
| before this round | 23 |
| + restore pointer cast on int address arithmetic | 23 |
| + retype `void *` parameters to int | **19** |
| + rewrite bare `*temp_v0` to `*(int *)temp_v0` | 29 — **worse, reverted** |

That last one is recorded deliberately: m2c uses those names for genuine
pointers too, so forcing the cast broke drafts that already compiled. It looked
obviously correct and was not.

Net for the round: 41 of 60 previously-failing drafts now compile, and the
project stands at **3,551 / 14,083 (2.73%)**. The extra matches were small
because the earlier broad run had already harvested what the arrow and
byte-arithmetic fixes enabled; this round mostly repaired damage those fixes
caused.

**The transferable lesson:** every rewrite added to the translation layer needs
re-measuring against a fixed sample, because fixing one artifact class routinely
creates another. Two of the three largest classes encountered this session were
introduced by the previous fix, not by m2c.
